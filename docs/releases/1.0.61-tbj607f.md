- Version code: `64`
- Variant: `googletvDebug`
- Application ID: `cn.codex.tbj607f.airplay`
- Minimum Android version for this variant: Android 10 (API 29). This release was tested from API 31 and above; API 29/30 compatibility was not revalidated.
- Target SDK: 35
- Signing: debuggable APK signed with the shared Lenovo-derived development certificate; not a production or store build. SHA-256 certificate fingerprint: `81A2C4315AC57E191F171468E833B68027FAA83DCDC29715310B72FA2F037400`.
- Source: GitHub branch `codex/public-release`; see the release tag for the exact source revision.

## Implemented in the app

- AirPlay receiver discovery through `_airplay._tcp` and `_raop._tcp` mDNS advertisements.
- AirPlay RTSP/HomeKit pairing and optional PIN protection.
- Receiver paths for AAC-ELD, AAC-LC, ALAC audio and H.264 screen mirroring, plus metadata/artwork and sender remote-control events. These paths are implemented in source; this prerelease does not claim end-to-end playback validation.
- Foreground receiver service, receiver status/device screens, protocol settings, and adaptive layouts for portrait phones, landscape, and tablet-sized screens. Clock seconds and volume controls have additional fit/edge spacing.
- Google Cast and Miracast control/setup code is present, but their media playback is not ready.

## Known incomplete behavior and open validation

- AirPlay 2 buffered audio (type 103) is accepted by the control path but is not played back.
- End-to-end AirPlay audio, screen mirroring, sender interoperability, and multi-room synchronization were not revalidated on v64. The verified mDNS discovery does not prove media playback works.
- The API 31 full phone-emulator run is incomplete because ADB disconnected; no app failure was isolated from that run.
- Google Cast and Miracast media playback remain unfinished. FairPlay-protected streaming video cannot be decrypted by this open-source receiver; Apple Music in-app audio may also be protected on AirPlay paths.

## Potential compatibility risks

- Wi-Fi access-point multicast filtering, AP isolation, and manufacturer battery policies can change discovery and background behavior. Only the listed physical devices were checked.
- Split-screen, uncommon aspect ratios, custom font/display scaling, and the wide range of Android OEM UI behaviors have not all been tested. Passing nine UI tests on each physical device does not cover every display configuration.
- This variant declares API 29 as its minimum, but v64 was not revalidated on API 29 or 30. API 31 was the oldest emulator target used for this milestone.
